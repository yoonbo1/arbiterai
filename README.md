# Arbiter AI monorepo

Arbiter AI (arbiterai.tech) is a HIPAA-oriented AI system for medical documentation:
documents are de-identified before any model sees them, answers are retrieved per patient,
verified, cited, and every job is written to an append-only audit log.

This repository holds two independent pieces:

```
platform/   The product. FastAPI gateway -> Redis Streams -> LangGraph workers -> Postgres+pgvector.
site/       The marketing site for arbiterai.tech. Static HTML generated by build.py into site/public/.
Makefile    Task runner: make site | up | down | synth | eval | test (see below).
CHANGELOG.md  What was changed from the original drop and why.
TODO.md       What is still required before real PHI (derived from platform/docs/HIPAA_CONTROLS.md).
```

## Layout

### platform/

| Path | Purpose |
|---|---|
| `gateway/` | FastAPI API gateway. Hashed API keys (HMAC-SHA256 with a pepper), scopes, per-key rate limits, tenant resolution from the key, admin endpoints for tenants and keys. Enqueues jobs, never runs inference. |
| `worker/` | Redis Streams consumer running two LangGraph graphs. Ingest: load -> route pages -> extract (text / OCR / VLM) -> Presidio de-identify -> chunk + embed -> audit. Query: de-identify question -> hybrid retrieval (pgvector + BM25, RRF) -> generate (small model) -> validate (PHI leak, citations, grounding) -> optional one-time escalation -> re-identify -> audit. |
| `db/init.sql` | Postgres schema: tenants, api_keys, patients, documents, chunks (vector(384)), phi_tokens (pgp_sym_encrypt), jobs, audit_log. Row-level security on every PHI table keyed on `app.tenant_id`. |
| `scripts/` | `make_synthetic_docs.py` (synthetic discharge summaries with known fake PHI, clean and "scanned"), `bootstrap_tenant.sh` (creates a tenant and mints a key against the local gateway). |
| `eval/run_eval.py` | 100-request harness: ingests the corpus, checks de-id recall on injected PHI, asks gold questions, reports accuracy, cross-patient leaks, p50/p95 latency. |
| `docs/` | `HIPAA_CONTROLS.md` (what the code covers vs what you must add), `CLOUD_OPTIONS.md` (scale-up plan), `CLIENT_CALL_PREP.md`. |
| `docker-compose.yml` | postgres (pgvector), redis, embeddings (text-embeddings-inference, bge-small), gateway, worker. GPU-only services (vLLM small model and VLM) are behind a compose profile. |

### site/

| Path | Purpose |
|---|---|
| `build.py` | Wraps each page body in the shared shell (header, nav, footer, meta, JSON-LD) and writes `public/`, `sitemap.xml`, `robots.txt`. |
| `pages.py`, `pages_home.py`, `pages_product.py` | Page bodies as HTML strings: home, product, security, pricing, docs, about, contact, privacy, terms, 404. |
| `assets/` | `styles.css` (ink / frost / brass palette), `main.js` (nav toggle, ledger animation, form handling), `logo.svg`, `favicon.svg`, `og-image.png`. |
| `netlify.toml`, `vercel.json`, `_headers` | Hosting config and security headers (CSP, HSTS, frame-ancestors none). |

`site/public/` is generated and is not committed. Run `make site` (or `python3 site/build.py` from `site/`).

## Quick start

Prerequisites: Docker (this repo was validated with Colima on Apple Silicon), Python 3.12,
and, for the language model on a machine without an NVIDIA GPU, Ollama
(`brew install ollama`, then `make llm` in a second terminal and `ollama pull qwen2.5:7b-instruct`).

Notes for this machine: there is no NVIDIA GPU, so the vLLM services stay behind the `gpu`
compose profile and the small-model tier is Ollama on the host, reached from containers at
`host.docker.internal:11434`. A Homebrew `postgresql@17` already owns port 5432, so the
compose Postgres is published on `127.0.0.1:${PG_HOST_PORT}` (55432 in `platform/.env`).

```bash
make venv            # Python 3.12 venv at .venv/ for host-side scripts and tests
make site            # build the marketing site into site/public/
make up              # postgres, redis, embeddings, gateway, worker (no GPU services)
make synth N=20      # synthetic documents with injected fake PHI -> platform/data/synthetic/
make bootstrap       # create a dev tenant + API key; writes platform/.env.dev-tenant (git-ignored)
make eval LIMIT=20   # run the eval harness against the local stack
make test            # pytest for gateway/auth.py, worker/deid.py, worker/retrieval.py
make logs            # follow gateway + worker logs
make down            # stop everything (make down-v also wipes the volumes)
```

On a box with NVIDIA GPUs, add the vLLM tiers with `docker compose --profile gpu up -d`
(and `--profile vlm` for the vision model) and point `SMALL_MODEL_URL` back at `vllm-small`.

See `platform/README.md` for the API and the isolation model, and `TODO.md` before
processing anything other than synthetic data.

## Non-negotiables

- Never send real PHI to this stack until the items in `TODO.md` are done.
- Cloud tracing (LangSmith, etc.) stays off. `LANGCHAIN_TRACING_V2=false`.
- `.env` files, `data/`, and keys are git-ignored. Do not commit secrets.
- The site must not claim SOC 2 or HITRUST until the reports exist.
