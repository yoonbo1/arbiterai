# The data, the ingestion pipeline, and every abbreviation

A reference for what exists in the system today, written from the actual rows on
2026-09-04. Section 1 is what data there is, section 2 walks one document through every
stage with the real output of each, section 3 is the glossary: every abbreviation and
proper noun used in this codebase, with the words it stands for, what it is, and why it is
here.

## 1. The data we have

Everything is synthetic. No real patient has ever been near this system. The corpus is
generated by `scripts/make_synthetic_docs.py` with the Faker library, seeded so it is
reproducible.

| what | where | count | notes |
|---|---|---|---|
| clean PDFs | `platform/data/synthetic/clean/` | 20 | one-page discharge summaries with a real text layer |
| scanned PDFs | `platform/data/synthetic/scan/` | 10 | every odd-numbered patient's clean PDF rasterized, rotated up to 1.5 degrees, blurred, thresholded, and saved as an image with no text layer |
| manifest | `platform/data/synthetic/manifest.json` | 20 records | the ground truth: the injected fake identifiers, the gold answers, and the gold clinical facts |
| size on disk | | 20 MB | |

Each record plants six identifiers that the de-identification eval must remove: a name, a
date of birth, a medical record number, a phone number with an extension, a street
address, and an attending physician. Each also carries two diagnoses, three medications,
an HbA1c, a blood pressure, an LDL, two negated findings, one family-history condition, and
one allergy or a note of no known allergies. The manifest is git-ignored along with the
PDFs; regenerate with `make synth N=20`.

What the database holds after ingesting all twenty, as of this writing:

| table | rows | what a row is |
|---|---|---|
| `tenants` | 2 | a customer organization; the second exists only to prove isolation |
| `api_keys` | 2 | one credential per tenant; stores a hash, never the key |
| `patients` | 22 | one per external id per tenant |
| `documents` | 22 | one per ingested file; status, page count, content hash |
| `chunks` | 21 | de-identified text pieces with a 384-number embedding; one per page here because the pages are short |
| `phi_tokens` | 181 | the encrypted map from placeholder to real value, per document |
| `clinical_facts` | 254 | structured facts extracted from the de-identified text |
| `jobs` | 359 | every ingest and query ever submitted, with tokens and cost |
| `audit_log` | 723 | append-only record of who did what |
| `schema_migrations` | 2 | which migration files have been applied |

The queue lives in Redis, not Postgres: one stream named `jobs`, one consumer group named
`workers`, plus short-lived cache entries for key lookups and rate-limit counters.

## 2. One document, stage by stage

Patient P00001, the scanned variant. The manifest says the real values are Joshua Duncan,
born 1975-06-15, MRN 8275367, phone +1-921-899-3518x19093, of 754 Laura Square Apt. 194,
Goldenmouth, LA 80318, seen by Dr. Baird on 2026-01-30. All invented.

**Stage 0, submission.** A client POSTs to `/v1/documents` with the patient's external id
and the file path. The gateway resolves the tenant from the API key, writes a `jobs` row
and an audit row in one transaction, then pushes the job id onto the Redis stream. The
client gets a 202 and a job id.

**Stage 1, load.** The worker opens the PDF with PyMuPDF and renders each page to a PNG at
200 dots per inch, keeping any native text layer. For this page the text layer is empty:
0 characters. That single fact decides everything that follows.

**Stage 2, route.** A page with more than 200 characters of native text is read for free.
This one has none, so Tesseract runs and reports its mean word confidence. Above 75 with
at least 40 words, the page is routed to OCR; otherwise to the vision model, or to OCR
with a flag if no vision model is configured, which is the case on this machine.

**Stage 3, extract.** Tesseract produces the page text. This is where the scan path pays
its price. Compare three lines of the original with what OCR produced:

```
original:  Patient: Joshua Duncan    DOB: 1975-06-15    MRN: 8275367
ocr:       Patient: Joshua Duncan DOB: 1975-06-15 MAN: 8275367
original:  Vitals and labs / BP 146/72   HbA1c 5.7%   LDL 98 mg/dL
ocr:       BP 146/72 HbAic 5.7% LDL 98 mg/dL
original:  Plan
ocr:       Pian
```

`MRN` became `MAN`, `HbA1c` became `HbAic`, `Plan` became `Pian`.

**Stage 4, de-identify.** Presidio runs over the OCR text with the spaCy language model
and the custom recognizers, and replaces each identifier with a numbered placeholder. The
de-identified page, which is what every later stage sees, reads:

```
Patient: <PERSON_5>: <DATE_TIME_2> MAN: 8275367
Phone: <PHONE_NUMBER_1> Address: <LOCATION_1>
Attending: <PERSON_4>. <PERSON_3> of service: <DATE_TIME_1>
Diagnoses
- major depressive disorder
- type 2 diabetes mellitus
- No evidence of syncope. Denies pneumonia.
Medications
- lisinopril 10 mg daily
- metformin 500 mg BID
- apixaban 5 mg BID
Allergies
penicillin (rash)
Vitals and labs
BP 146/72 HbAic 5.7% LDL 98 mg/dL
<PERSON_2>
Follow up with Dr. <PERSON_1> in 2 weeks. Continue current medications. Low-sodium diet.
Family history of type 2 diabetes mellitus.
```

The map from placeholder to value is encrypted with the tenant's key and stored in
`phi_tokens`. Decrypted with the right key, it reads:

| placeholder | type | value |
|---|---|---|
| `<DATE_TIME_1>` | DATE_TIME | 2026-01-30 |
| `<DATE_TIME_2>` | DATE_TIME | 1975-06-15 |
| `<LOCATION_1>` | LOCATION | 754 Laura Square Apt. 194, Goldenmouth. LA 80318 |
| `<PERSON_1>` | PERSON | Baird |
| `<PERSON_2>` | PERSON | Pian |
| `<PERSON_3>` | PERSON | Baird Date |
| `<PERSON_4>` | PERSON | Dr |
| `<PERSON_5>` | PERSON | Joshua Duncan DOB |
| `<PHONE_NUMBER_1>` | PHONE_NUMBER | +1-921-899-3518x19093 |

Decrypted with another tenant's key, Postgres answers "Wrong key or corrupt data".

Read the map honestly and you can see three things. The identifiers that matter were
caught: the name, both dates, the address, the phone number. The span boundaries on OCR
text are sloppy: `<PERSON_5>` swallowed the label `DOB`, `<PERSON_3>` is "Baird Date",
and `<PERSON_2>` is the OCR-mangled header `Pian`, mistaken for a surname. And one
identifier escaped: the MRN, because its label had become `MAN:` and the recognizer is
anchored on the label. That one survivor is why de-identification recall on the
regenerated corpus is 0.992 rather than 1.0, and it is the top item in `TODO.md`. The
sloppiness is recoverable, because re-identification restores exactly what was removed,
but it costs the next stage a section header.

**Stage 5, annotate.** The clinical NLP layer reads the de-identified page and writes
structured facts. For this page, 12 rows:

| kind | assertion | normalized | attributes | section | extractor |
|---|---|---|---|---|---|
| problem | present | major depressive disorder | | diagnoses | rules |
| problem | present | type 2 diabetes mellitus | | diagnoses | rules |
| problem | absent | syncope | | diagnoses | ner |
| problem | absent | pneumonia | | diagnoses | ner |
| problem | family | type 2 diabetes mellitus | | labs_and_studies | rules |
| medication | present | lisinopril | dose 10 mg, frequency daily | medications | rules |
| medication | present | metformin | dose 500 mg, frequency BID | medications | rules |
| medication | present | apixaban | dose 5 mg, frequency BID | medications | rules |
| allergy | present | penicillin | reaction rash | allergy | rules |
| lab | present | hba1c | value 5.7, unit % | labs_and_studies | rules |
| lab | present | ldl | value 98, unit mg/dL | labs_and_studies | rules |
| vital | present | bp | value 146/72, unit mmHg | labs_and_studies | rules |

Two things to notice. "No evidence of syncope" and "Denies pneumonia" are stored as
`absent`, and the family-history line as `family`, so a query for this patient's
problems will never list pneumonia as something they have. And the family-history fact
is sectioned as `labs_and_studies` rather than `observation_and_plan`, because the
`Plan` header was destroyed two stages earlier. The fact is still correct; only its
section label is off. Every fact points at chunk 128 and carries `<DATE_TIME_1>`, the
nearest date placeholder, so a later query can restore the service date for the caller.

**Stage 6, chunk and embed.** The page text is split into pieces of up to 800 characters
with 120 characters of overlap, preferring to split at headings and blank lines. This
page is one chunk. Each chunk is sent to the embeddings service and comes back as 384
numbers, stored in `chunks` next to the text, the page, the extraction route, and its
character offsets on the page. The row for this page:

```
id 128, page 1, extraction ocr, offsets [0, 584), embedding 384 floats
first four: -0.0606, 0.0390, -0.0140, 0.0053
```

Only de-identified text is ever embedded. The vector index is not PHI.

**Stage 7, audit.** The `jobs` row is marked done with the validation summary, and an
audit row is written:

```
jobs:      f9fc0185  ingest  done  {facts: {lab 2, vital 1, allergy 1, problem 5, medication 3},
                                    pages 1, facts_total 12, chunks_indexed 1, vlm_wanted_pages 0}
audit_log: worker  job.ingest.completed  patient f7480b2c...  {pages 1, routes {ocr 1}, facts ...}
```

The worker then acknowledges the Redis message. Wall time for the whole job on this
machine: about two seconds, of which annotation was 39 milliseconds.

**What a query then does with it.** A question about P00001 is de-identified the same way,
embedded, matched against this tenant's and this patient's chunks only, re-ranked with
keyword matching, answered by the local model with a citation to `[128]`, checked for
leaks, citations and grounding, and finally re-identified for the caller. The two query
jobs visible for this patient both passed all three checks with a faithfulness score of
1.0 and cost about 0.013 cents each at the placeholder rates.

## 3. Glossary

Every abbreviation and named component in the codebase, grouped. For each: the words, what
it is, and why it is here.

### Healthcare and regulation

- **HIPAA**, Health Insurance Portability and Accountability Act. The 1996 US law whose
  Privacy and Security Rules govern how health information is handled. Why: it is the
  legal frame the whole product is built to satisfy; "HIPAA-oriented" in the README means
  designed to meet its safeguards, not certified, because no such certification exists.
- **PHI**, Protected Health Information. Any health information that can identify a
  person. Why: the thing the system must never leak; de-identification exists to convert
  PHI into non-PHI before a model sees it.
- **BAA**, Business Associate Agreement. The contract HIPAA requires between a covered
  entity such as a clinic and a vendor that handles PHI on its behalf. Why: a tenant with
  no `baa_signed_at` cannot get a working API key, so the contract is enforced in code.
- **Safe Harbor.** One of two HIPAA de-identification methods: remove eighteen listed
  identifier types (names, dates except year, geography smaller than a state, phone, MRN,
  SSN, and so on). Why: it defines what the de-identifier must catch, and why "daily" is
  not a date but "March 9" is.
- **MRN**, Medical Record Number. A hospital's internal patient identifier. Why: an
  explicit Safe Harbor identifier, and one Presidio does not recognize by default, hence
  the custom recognizer.
- **DOB**, Date of Birth. Why: a Safe Harbor date; also the label that OCR text merges
  into names.
- **SSN**, Social Security Number. Why: a Safe Harbor identifier; Presidio rejects the
  textbook fake 123-45-6789, which is why one test is marked expected-fail.
- **NKDA**, No Known Drug Allergies. Why: the allergy section can say this instead of
  listing anything, and the extractor must produce no allergy fact for it.
- **BID, PRN, qhs, daily.** Latin-derived dosing frequencies: twice a day, as needed, at
  bedtime, once a day. Why: they are the frequency attribute on medication facts, and
  "daily" was being scrubbed as a date until the date filter was added.
- **HbA1c**, glycated hemoglobin A1c. A blood test reflecting three months of average
  glucose. Why: the synthetic gold question asks for it, and its OCR misspellings
  (HbAic, HbAt1c) drove the widened lab pattern.
- **LDL**, low-density lipoprotein cholesterol. Why: a second lab in the synthetic
  documents so the extractor is scored on more than one.
- **BP**, blood pressure. Why: the vital sign in every synthetic document.
- **CAD, COPD, CKD**, coronary artery disease, chronic obstructive pulmonary disease,
  chronic kidney disease. Why: diagnoses in the synthetic pool.
- **EHR**, Electronic Health Record. The system a clinic keeps charts in. Why: where
  documents come from in production and what a prospective product would integrate with.
- **ICD-10-CM**, International Classification of Diseases, tenth revision, Clinical
  Modification. The US diagnosis code set. Why: what a problem fact should normalize to,
  and what maps onto HCCs; public domain in the US.
- **RxNorm.** The National Library of Medicine's normalized drug vocabulary. Why: what a
  medication fact should normalize to; the prescribable subset is free to redistribute.
- **LOINC**, Logical Observation Identifiers Names and Codes. The code set for lab tests
  and observations. Why: what a lab fact should normalize to; free with a license.
- **SNOMED CT**, Systematized Nomenclature of Medicine, Clinical Terms. The most
  comprehensive clinical terminology. Why: the richest normalization target, but it
  requires the customer to hold an affiliate license.
- **UMLS**, Unified Medical Language System. NLM's umbrella that bundles the above
  vocabularies. Why: several NLP tools link to it, and its license forbids redistributing
  the databases, which is why MedCAT and scispaCy's UMLS linker were not adopted.
- **NLM, CDC, CMS, OIG.** National Library of Medicine, Centers for Disease Control,
  Centers for Medicare and Medicaid Services, Office of Inspector General. Why: NLM
  publishes RxNorm and UMLS; CDC publishes the ICD-10-CM files; CMS publishes the HCC
  model and audits plans; OIG issued the 2026 guidance on chart review.
- **HCC**, Hierarchical Condition Category. CMS's grouping of diagnoses into categories
  that adjust Medicare Advantage payments. Why: the retrospective risk-adjustment product
  in the roadmap maps ICD-10-CM codes to HCCs using CMS's public crosswalk.
- **RAF**, Risk Adjustment Factor. The per-member score that HCCs build. Why: what health
  plans are ultimately trying to get right; Reveleer's metrics are stated in RAF.
- **V28.** The current CMS-HCC model version, at full weight for 2026. Why: the mapping
  file the roadmap points at.
- **MEAT**, Monitor, Evaluate, Assess, Treat. The four kinds of documentation evidence that
  a diagnosis was actively managed at an encounter. Why: a code with no MEAT evidence is
  unsupported; the roadmap's condition-validation feature attaches MEAT evidence with
  page citations.
- **RADV**, Risk Adjustment Data Validation. CMS's audit of whether a plan's submitted
  diagnoses are supported by the chart. Why: the audit-packet feature in the roadmap.
- **HEDIS**, Healthcare Effectiveness Data and Information Set. The standard set of quality
  measures health plans report. Why: the measure-evidence feature; its specifications
  need an NCQA license to implement in software.
- **NCQA**, National Committee for Quality Assurance. The body that owns HEDIS. Why: the
  licensor.
- **ECDS**, Electronic Clinical Data Systems. NCQA's digital reporting path for HEDIS.
  Why: the direction that turns annual abstraction into a continuous pipeline.
- **CDI**, Clinical Documentation Improvement. The hospital function that improves chart
  documentation. Why: a buyer persona for evidence packets.
- **n2c2, i2b2.** National NLP Clinical Challenges and Informatics for Integrating Biology
  and the Bedside. The shared-task datasets clinical NLP is benchmarked on. Why: the only
  credible way to evaluate extraction on real notes; each needs a data use agreement.

### Security and isolation

- **API**, Application Programming Interface. Why: the gateway is one; clients integrate
  with two endpoints.
- **HMAC**, Hash-based Message Authentication Code, with **SHA-256**, Secure Hash
  Algorithm 256-bit. A keyed hash. Why: API keys are stored as HMAC-SHA256 of the key
  under a server-side secret, so a database dump yields nothing usable.
- **Pepper.** A secret mixed into every hash, kept outside the database. Why: a
  database-only breach cannot verify a guessed key; rotating it invalidates all keys.
- **TTL**, Time To Live. How long a cache entry or DNS record stays valid. Why: key
  lookups are cached in Redis for sixty seconds so revocation lands within a minute.
- **UUID**, Universally Unique Identifier. A 128-bit random or derived id. Why: every job,
  tenant, key, patient and document id; idempotent job ids are derived with UUID version
  five from the key and the idempotency key.
- **Idempotency key.** A client-chosen token sent with a request so retries are
  recognized. Why: a network retry maps to the same job instead of a duplicate.
- **RLS**, Row-Level Security. A Postgres feature where policies filter every query on a
  table. Why: the database refuses to return another tenant's rows regardless of the
  application's SQL; only real if the app connects as a role the policies apply to, which
  was the biggest fix of the bring-up.
- **DEK, KEK.** Data Encryption Key, Key Encryption Key. The key that encrypts data, and
  the key that protects it. Why: `TENANT_KEK` plus the tenant id derives each tenant's map
  key today; production replaces that with a KMS-issued DEK per tenant.
- **KMS**, Key Management Service. A managed system that issues, rotates and audits keys.
  Why: the production home for tenant keys.
- **pgcrypto, pgp_sym_encrypt.** A Postgres extension and its symmetric-encryption
  function following the OpenPGP format. Why: the placeholder map is encrypted inside the
  database, so plaintext never crosses into application memory except at ingest and
  re-identification.
- **JSON, JSONB.** JavaScript Object Notation; Postgres's binary, indexable form of it.
  Why: job requests, results, audit detail and fact attributes are JSONB.
- **TLS, SSL, HTTPS.** Transport Layer Security, its predecessor's name, and HTTP over
  it. Why: required between every component before real PHI; today only the public site
  has it.
- **SIGTERM.** The termination signal a container runtime sends on shutdown. Why: the
  worker finishes its current job on SIGTERM instead of dropping it.
- **Health check.** A probe a container runtime runs to decide a service is ready. Why:
  the worker only starts after Postgres, Redis and the embeddings service pass theirs.

### Pipeline and retrieval

- **RAG**, Retrieval-Augmented Generation. Answer questions by retrieving relevant text
  and giving it to a model rather than relying on the model's memory. Why: the entire
  query graph; it is what makes every answer citable.
- **Chunk.** A piece of a document small enough to embed and retrieve. Why: 800
  characters with 120 overlap, split at headings first so a medication list stays whole.
- **Embedding.** A list of numbers representing a text's meaning so similar texts are
  near each other. Why: how retrieval finds paraphrases; 384 numbers per chunk here.
- **pgvector, HNSW, cosine.** A Postgres extension for vectors; Hierarchical Navigable
  Small World, its index structure; cosine similarity, the distance it uses. Why: the
  vector store lives in the same database as everything else, under the same RLS.
- **BM25**, Best Match 25. A keyword ranking function. Why: vector search misses exact
  terms like drug names; BM25 catches them.
- **RRF**, Reciprocal Rank Fusion. Combine two rankings by summing 1/(60 + rank). Why:
  merges vector and keyword results without tuning weights.
- **LLM**, Large Language Model. Why: writes the answer and judges grounding; the small
  tier here is a 7-billion-parameter Qwen model.
- **VLM**, Vision Language Model. A model that reads images. Why: the intended route for
  forms and handwriting; not available on this machine, so those pages fall back to OCR.
- **OCR**, Optical Character Recognition. Turning a page image into text. Why: half the
  synthetic corpus and most real fax intake has no text layer.
- **Tesseract.** The open-source OCR engine. Why: cheap and local; its confidence score is
  the routing gate; its misreads are the source of every residual eval miss.
- **DPI**, dots per inch. Render resolution. Why: pages are rendered at 200 for OCR.
- **PDF, PNG.** Portable Document Format; Portable Network Graphics. Why: the input
  format and the rendered page format.
- **PyMuPDF** (imported as `fitz`). A PDF library. Why: renders pages and reads text layers.
- **NLP**, Natural Language Processing. Why: the field; clinical NLP is the annotate layer.
- **NER**, Named Entity Recognition. Finding spans of a given type, such as drugs or
  diseases. Why: the problem and medication models are NER models.
- **spaCy.** An NLP library. Why: the engine under Presidio, medspacy and both clinical
  models; `en_core_web_lg` is its large English model.
- **Presidio.** Microsoft's open-source de-identification framework. Why: runs the
  recognizers, reconciles their results, and is where the custom MRN, phone, name and
  address recognizers plug in.
- **medspacy.** A clinical extension of spaCy. Why: section detection, sentence splitting
  and assertion.
- **ConText.** The rule-based algorithm medspacy uses to decide whether a finding is
  negated, historical, hypothetical, uncertain, or about a family member. Why: the reason
  "denies chest pain" is stored as absent rather than as a chest-pain diagnosis.
- **PyRuSH**, Python Rule-based Sentence Segmenter using Hashing. Why: medspacy's
  sentence splitter; it logs document text at debug level unless disabled, which it is.
- **Med7.** A spaCy model for medication entities and their attributes. Why: dose, route
  and frequency extraction.
- **bc5cdr.** BioCreative V Chemical Disease Relation, the corpus its model was trained
  on. Why: the disease-span model.
- **LangGraph.** A library for building explicit state-machine pipelines over model
  calls. Why: the ingest and query graphs; each node is a plain function and the branching
  is visible.
- **Checkpointer.** LangGraph's optional state persistence after each node. Why: off by
  default, because the state holds pre-scrub text and the plaintext map.
- **Redis Streams.** Redis's append-only log with consumer groups. **XADD** appends,
  **XREADGROUP** reads on behalf of a group, **XACK** acknowledges, **XAUTOCLAIM** takes
  over messages a dead consumer left pending. Why: the job queue, with crash recovery.
- **At-least-once.** A delivery guarantee: a message may be processed more than once but
  never zero times. Why: the honest guarantee; ingest is made idempotent to tolerate it.
- **FastAPI.** A Python web framework. Why: the gateway and the embeddings service.
- **asyncpg, psycopg.** Two Postgres drivers. Why: the gateway is asynchronous and uses
  asyncpg; the worker is synchronous and uses psycopg 3, whose missing `executemany` on
  connections was the first crash of the bring-up.
- **fastembed, ONNX, bge-small.** A CPU embedding library; Open Neural Network Exchange,
  the model format it runs; BAAI General Embedding small, the model. Why: the upstream
  embeddings image is x86-only, so this replaces it on Apple Silicon.
- **TEI**, Text Embeddings Inference. Hugging Face's embeddings server. Why: the original
  choice, kept as a comment for x86 hosts.
- **Ollama.** A local model runner with an OpenAI-compatible API. Why: serves the 7B model
  on this Mac using its GPU.
- **vLLM.** A high-throughput model server for NVIDIA GPUs. Why: the production model
  tier, behind the `gpu` compose profile; cannot run here.
- **AWQ**, Activation-aware Weight Quantization. A way to shrink a model to 4-bit
  weights. Why: the vLLM model name in the compose file is an AWQ build so it fits one GPU.
- **Faker, Synthea.** A fake-data library; an open-source synthetic patient generator.
  Why: Faker makes the corpus today; Synthea is the richer option the script accepts.

### Infrastructure and site

- **Docker, Compose.** Container runtime; multi-container definitions. Why: the five
  services and their health-check ordering.
- **Colima.** A container runtime for macOS. Why: this Mac had no Docker installed.
- **DNS, A record, CNAME, ALIAS.** Domain Name System; an address record; a canonical-name
  alias; a provider-flattened alias usable at a bare domain. Why: `www` is a CNAME to
  Heroku; the bare domain cannot be, and Squarespace forbids ALIAS on a DNSSEC zone.
- **DNSSEC**, DNS Security Extensions. Cryptographic signing of DNS answers. Why: enabled
  on the domain, and the reason the apex still forwards rather than pointing at Heroku.
- **ACM**, Automated Certificate Management. Heroku's Let's Encrypt integration. Why:
  issued the site's certificate once DNS pointed at it.
- **CSP, HSTS.** Content Security Policy; HTTP Strict Transport Security. Browser-enforced
  headers. Why: applied by the site's server since the static-host header files do not
  apply on Heroku.
- **OG**, Open Graph. Meta tags social sites read for link previews. Why: the generated
  1200 by 630 image.
- **WSGI, gunicorn, WhiteNoise.** The Python web-server interface; a server that speaks
  it; a static-file middleware. Why: the marketing site's production stack.
- **Dyno.** Heroku's unit of compute. Why: the site runs on one; Eco sleeps, Basic does not.
- **CDN**, Content Delivery Network. Why: Squarespace's cached the parking page at the root.

### Evaluation

- **Precision, recall, F1.** Of what was extracted, how much was right; of what should
  have been extracted, how much was found; their harmonic mean. Why: the extraction eval
  reports all three per fact kind, and de-identification is judged on recall because a
  missed identifier is a breach and an over-scrubbed word is an inconvenience.
- **Strict recall.** De-identification recall where any surviving component of a
  multi-part identifier counts as a miss. Why: the whole-string check hid surviving street
  lines and ZIP codes.
- **Cross-patient leak.** An answer for one patient containing another's identifier. Why:
  the isolation gate; zero in every run.
- **p50, p95.** The median and the 95th percentile of latency. Why: what a user typically
  waits and what the slow tail looks like.
